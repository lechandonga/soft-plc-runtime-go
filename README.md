# 本地软 PLC 运行时（Go）

用纯 Go 标准库实现的软 PLC 运行时。控制器、现场 I/O、程序文件、保持数据全部在本地模拟，
不依赖网络、外部服务、真实硬件或任何第三方 Go 模块。

目标是在异常时序（看门狗、执行异常、I/O 失联、写文件中断）和进程重启之后，
程序加载、循环扫描、掉电保持三块都给出确定、可解释的结果。

## 目录结构

| 路径 | 说明 |
| --- | --- |
| `plc/program.go` | 程序文件两遍解析与启动前全量校验 |
| `plc/addr.go` | 地址、标签、立即数的词法与合法性 |
| `plc/config.go` | JSON 配置加载与逐项校验 |
| `plc/io.go` | I/O 模块接口与本地内存模拟实现（可掉线/延迟/故障注入） |
| `plc/runtime.go` `plc/scan.go` | 扫描周期、状态元件、看门狗、故障安全 |
| `plc/state.go` `plc/lifecycle.go` | 保持数据原子落盘、兼容判定、热重载、故障复位 |
| `plc/*_test.go` | 全量本地测试（含 `-race` 并发用例） |
| `cmd/plc/main.go` | 本地可运行的命令行演示 |
| `examples/conveyor.plc` `examples/config.json` | 示例控制程序与配置 |

## 程序文件格式

文本、逐行、大小写不敏感的指令表（IL 风格）。空行与 `#` 之后的内容是注释。

```text
VERSION 1                       # 程序版本号，正整数；保持数据身份的一部分
TAG start = X0                  # 标签绑定到直址，语法 TAG 名称 = 地址

LD   start                      # 取触点值压入能流栈
SET  Y0                         # 能流为真则置位线圈
LD   X1
RST  Y0                         # 能流为真则复位线圈（也可 RST Tn/Cn）
LD   Y0
OUT  Y1                         # 每周期用能流无条件覆盖输出

LD   X0
TON  T0 K3000                   # 接通延时定时器，K 后为毫秒，3000ms 到点
LD   X2
CTU  C0 K10                     # 上升沿加 1 计数器，K 后为预设值
LDP  X3                         # X3 上升沿（off->on）一个周期
ANDF X4                         # 与 X4 下降沿（on->off）
MOV  K42 D0                     # 立即数写入数据字

LD   X5
JMP  bypass                     # 条件跳转，目标标号必须存在
LBL  bypass
END                              # 程序必须以 END 结束
```

支持的指令：

| 类别 | 指令 |
| --- | --- |
| 触点 | `LD LDI LDP LDF`、`AND ANI ANDP ANDF`、`OR ORI ORP ORF` |
| 线圈 | `OUT SET RST` |
| 状态元件 | `TON Tn K毫秒`、`CTU Cn K预设`、`MOV K值 Dn` |
| 控制 | `JMP 标号`、`LBL 标号`、`END` |
| 声明 | `VERSION n`、`TAG 名 = 地址` |

地址空间：

| 前缀 | 含义 | 范围 |
| --- | --- | --- |
| `X` | 数字量输入 | `X0..X999` |
| `Y` | 数字量输出 | `Y0..Y999` |
| `M` | 内部位 | `M0..M999` |
| `T` | 定时器（完成位、累计毫秒） | `T0..T255` |
| `C` | 计数器（完成位、当前值） | `C0..C255` |
| `D` | 数据字 | `D0..D999` |

### 启动前校验（任何一条失败都整体拒绝）

错误原因互不混用，可用 `errors.Is` 精确区分；`*plc.LoadError` 还带行号与原始文本：

- `ErrSyntax`：参数个数不对、立即数非法、缺 `END`、首指令非法等；
- `ErrUnknownInstruction`：助记符不在指令表内；
- `ErrInvalidAddress`：地址前缀/范围非法、触点引用 `D` 字、`TON` 目标不是 `T` 等；
- `ErrInvalidTag`：标签名非法或与直址重名；
- `ErrMissingReference`：引用了未定义标签、`JMP` 目标标号不存在；
- `ErrDuplicateDefinition`：标签/标号重复定义，同一元件出现两处 `OUT`。

不存在“加载到一半再用默认值顶替”的路径：解析失败返回 `nil` 程序，运行时不会得到半成品。

## 循环扫描语义

每个周期严格分三阶段，顺序不可见地交错：

1. **输入采样**：向 I/O 模块请求一次输入快照（map 的拷贝）。整个周期内程序只看这份快照，
   现场线程在阶段 2/3 的任何抖动要到下一周期才可见。
2. **程序执行**：指令在从“上一个已提交状态”复制出的工作区里逐行解释执行。
   输出在这一阶段对外部完全不可见；执行异常会丢弃整个工作区，不污染当前状态。
3. **输出提交**：一次性把本周期全部 Y 点写回 I/O 模块。未在程序中驱动的 Y 点保持上周期值。

确定性规则：

- 相同程序、相同配置、相同输入序列 ⇒ 逐周期输出逐拍相同（`TestScanReproducible`）。
- 定时器按周期数累计毫秒（`周期 × cycle_interval_ms`），到点置完成位，失能立即清零。
- 计数器只认能流上升沿，常按不多计；`RST Cn` 与 `CTU Cn` 同周期时复位优先。
- `P/F` 边沿触点与“上一周期已提交值”比较；同一周期多次引用同一触点结果一致。
- `JMP` 只能向前/向后跳到已定义标号，必须有前置能流。
- 同一 `Y/M` 元件禁止两处 `OUT`（避免不确定的双线圈），`SET/RST` 允许标准启保停组合。

### 看门狗

每个周期有两道独立的硬上限，任何一道超限都进入 `WATCHDOG` 故障：

- 墙钟时间 `watchdog_ms`：在执行钩子前后及每 8 条指令的检查点比较截止时刻；
- 指令条数 `instruction_budget`：确定性地约束死循环/超长程序，测试无需依赖时序。

### 故障与安全输出

故障类别彼此可区分（`Fault.Code`，并实现 `Unwrap` 以支持 `errors.Is`）：

| 故障 | 触发 | 哨兵错误 |
| --- | --- | --- |
| `WATCHDOG` | 墙钟或指令预算超限 | `ErrWatchdog` |
| `EXEC` | 指令栈非法、钩子注入异常等 | `ErrExecException` |
| `IO_LOST` | 输入采样或输出提交超时/返回错误 | `ErrIOLost` |
| `STATE_WRITE` | 保持数据原子写失败 | `ErrStateFault` |

进入故障的瞬间：

- 周期停止推进，程序不再执行；
- 所有程序涉及的 Y 点按 `safe_outputs` 配置落安全值（未配置即 `false`），并尽力写回 I/O；
- 第一个故障的代码、周期号、原因被锁定，后续问题不覆盖它；
- **绝不自动恢复**。只有显式调用 `Reset()` 才尝试恢复，且必须满足：
  - `WATCHDOG/EXEC`：人工显式确认（复位后同一程序仍会再次超时/异常，不会悄悄换逻辑）；
  - `IO_LOST`：I/O 模块必须通过一次读探测和一次写探测；
  - `STATE_WRITE`：必须成功完整写入一份新快照。

## 热重载原子性

`Runtime.Reload(reader)` 与扫描互斥（同一把锁），语义是“全有或全无”：

1. 新程序先走完整的启动前校验，任何错误都拒绝，运行时继续执行旧程序；
2. 用当前 `state_file` 对新程序做身份兼容检查（见下），不兼容默认拒绝；
3. 只有全部通过，才一次性切换 `prog`、重置非保持状态、清零周期计数与故障态。

不存在新旧指令混跑的中间窗口：扫描要么看到整个旧程序，要么看到整个新程序。

## 掉电保持

### 哪些数据保持

由配置 `retain` 显式列出，仅允许 `T/C/D`（内部位保留扩展）。
未列出的元件一律按冷启动处理，不“猜默认”。清单排序后写入快照清单，作为身份的一部分。

### 提交与崩溃窗口

- 快照包含程序版本、结构摘要、保持地址清单，以及全部保持元件的完整值；
- 落盘流程：写同目录临时文件 → `Sync` → `Rename` 原子替换，
  外加 `魔数 + 长度 + JSON + SHA-256 校验和`。
  写到一半（进程被杀、磁盘满、断电）时，目录里要么是旧文件要么是完整新文件，不会出现半成品生效；
- 快照只在“输出成功提交之后”生成，因此最近一次完整提交的含义是明确的：
  未走完整个周期（含输出提交）的状态，崩溃后确定丢失。

### 程序身份与兼容性结论

重启或热重载时，三道检查依次给出**明确结论**，不通过宁可拒绝，绝不错位加载：

1. `ErrVersionMismatch`：`VERSION` 不一致；
2. `ErrLayoutMismatch`：版本相同但结构摘要不同
   （任何指令增删、元件/标签绑定变化都会改变摘要；仅注释/空白变化不影响）；
3. `ErrRetainMismatch`：保持地址集合与文件清单不一致。

文件不存在是确定的“冷启动”。文件头非法、长度不符、校验和不过统一报
`ErrStateCorrupt`（其中包装上面的具体类别），并说明是“写了一半”还是“内容损坏”。
只有显式配置 `allow_discard_state=true` 时，才允许把不兼容的旧数据明确丢弃后冷启动，
日志会留下该决定的原因。

## 配置项（JSON）

见 `examples/config.json`：

| 字段 | 含义 |
| --- | --- |
| `cycle_interval_ms` | 扫描周期目标长度（正整数） |
| `watchdog_ms` | 单周期程序执行墙钟上限（正整数） |
| `instruction_budget` | 单周期指令执行条数上限（确定性看门狗） |
| `io_sample_timeout_ms` | 单次输入采样/输出提交超时 |
| `safe_outputs` | 故障时各 Y 点的安全值，未列出即 `false` |
| `retain` | 需要掉电保持的地址排序列表，仅 `T/C/D` |
| `state_file` | 保持数据文件路径 |
| `persist_every_cycle` | 是否每个周期末尾原子落盘一次 |
| `allow_discard_state` | 是否允许明确丢弃不兼容的旧保持数据 |

配置同样严格校验：非法周期/看门狗/预算/超时、空状态文件路径、安全点不是 `Y`、
保持点不是 `T/C/D`、保持点重复等都会以 `ErrInvalidConfig` 拒绝启动。

## 本地验证

全部验证只需要 Go 工具链，不需要网络、硬件或第三方依赖：

```bash
go vet ./...
go test -count=1 ./...
CGO_ENABLED=1 go test -race -count=1 ./...     # 竞态检测

go run ./cmd/plc -program examples/conveyor.plc \
  -config examples/config.json -cycles 600
```

测试覆盖与可解释性：

- 每个用例通过统一日志输出 `[业务] 覆盖点 | [输入] 构造的程序/时序 | [判定] 预期与依据`，
  `go test -v` 可直接审阅测试覆盖了哪些业务场景；
- 主要场景：加载按原因拒绝、不得部分加载、热重载原子性、版本/结构/保持集合不兼容、
  扫描三阶段隔离、可复现、定时器/计数器/边沿确定、条件跳转、
  两类看门狗、执行异常、I/O 掉线与恢复条件、禁止自动恢复、
  重启恢复最近提交、未提交周期丢失、截断/校验和损坏文件拒绝、
  I/O 与扫描并发的 `-race` 稳定性。

模拟 I/O 提供了确定性的故障注入手段：`SetOffline`、`SetDelay`、`FailNext`，
因此看门狗超时、I/O 失联、恢复探测等时序都可以在测试中稳定复现，不依赖真实时钟抖动。
