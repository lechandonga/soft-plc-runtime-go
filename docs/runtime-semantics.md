# 扫描与故障语义

## 循环扫描三（四）阶段

每个扫描周期严格按顺序执行，全部由运行时单把互斥锁串行化：

1. **输入采样**：通过 I/O 接口一次性 `Read` 整包输入到过程映像。整包快照在本周期内不变，
   程序执行期间外部设备如何更新都不会被当前周期看到（无半更新输入）。
2. **程序执行**：在过程映像上跑完整程序；输出只写输出映像，不对外部设备产生任何效果。
   执行前保存“周期前完整快照”，执行异常时整份回滚，周期内的中间写入一个都不保留。
3. **输出提交**：一次性 `Write` 整包新输出映像，外部只看到完整新包（无半更新输出）。
4. **保持提交**（启用时）：从已提交状态抽取保持项，原子写入保持文件（见 `docs/retain.md`）。

只有四阶段全部成功，扫描计数才加 1，并把当前数据表登记为“最近一次完整提交状态”。

## 确定性与可复现

- 输入采样是整包快照；执行阶段不访问任何外部输入。
- 定时器以 `scan_period_ms` 为固定时间基，不用墙钟累计，因此相同输入序列与配置产生逐拍相同结果
  （见 `TestScanConsistency`：两次独立运行的边沿轨迹逐拍一致）。
- 边沿检测历史以指令位置为键；计数器在输入的上升沿动作，复位具有优先级。

## 单周期保护（两道，互相独立）

两道保护各自独立触发，谁先触发算谁，故障原因可区分：

1. **指令条数预算**（`watchdog_instructions`，默认 100000）：在每条指令执行前扣减，
   预算耗尽立即停止执行并进入 `WatchdogFault`——即使程序含死循环也会在确定步数内终止，
   不依赖墙钟、不会卡死进程。
2. **墙钟耗时上限**（`scan_time_limit_ms`，默认 0 = 关闭）：从输入采样开始，
   到输出提交完成为止的整轮真实耗时超过上限即进入 `ScanTimeoutFault`。
   覆盖“指令没几条、但就是跑得慢”的情形；关闭时行为与引入该配置前完全一致。

任一触发后的处置相同：当轮整体回滚（超时/超限前的半截执行结果一点都不保留，
本周期任何中间状态都不会被后续周期继续使用）、输出整包落安全值、故障锁存，
只能显式 `Recover()`，不会因 I/O 重连等外部变化自行恢复。

## 故障状态（可区分、锁存、不自动恢复）

| 故障 | 触发 |
| --- | --- |
| `IOFault` | 输入采样失败 / I/O 不健康 / 输出提交失败（含模拟模块断线） |
| `WatchdogFault` | 单周期指令条数超预算 |
| `ScanTimeoutFault` | 单周期墙钟耗时超 `scan_time_limit_ms` 上限 |
| `ExecutionFault` | 执行期异常（地址越界等，解析期无法预见的情形） |
| `RetainFault` | 保持快照构造或保持文件提交失败 |
| `StartupFault` | 启动期保持数据不兼容（直接拒绝启动，见保持文档） |

进入任一故障时运行时都会：

1. 回滚到周期前已提交状态（故障周期的半成品全部消失）；
2. 把输出映像整包置为**安全值**（见配置 `safe_outputs`，未列出的输出清 0），并尝试向 I/O 下发；
3. 锁存故障：后续 `Scan` 直接返回该故障，扫描计数不增加——**不会因为 I/O 重连而悄悄自动恢复**。

## 恢复的明确条件（必须显式 `Recover()`）

1. 当前确有锁存故障（正常状态调用恢复会报错，避免把恢复当复位滥用）；
2. I/O 报告 `Healthy()`，且一次试读输入、一次安全值试写都成功；
3. `RetainFault` 还要求保持存储可写：用“最近一次完整提交状态”成功试提交一份保持快照。

恢复后以最近一次完整提交状态为基线继续运行，故障周期的任何中间状态都不存在。
在模拟 I/O 中，`Disconnect()` 后仅 `Reconnect()` 不会恢复扫描，必须再调用 `Recover()`。

## 本地故障演练（执行异常注入，默认关闭）

“程序执行自身出错”（`ExecutionFault`）这条链路可以通过配置 `fault_injection`
确定性地演练，无需真撞上内部错误：

- 指定周期号（`exec_error_scans`）与指令序号（`at_instruction`），执行到该指令前
  抛出演练异常，进入 `ExecutionFault`——与 `IOFault`/`WatchdogFault`/
  `ScanTimeoutFault`/`RetainFault` 都可区分；
- 异常点之前已执行的半截写入随当轮整体回滚，异常点之后本周期不再执行；
- 输出整包落安全值、故障锁存，任何外部条件变化都不会悄悄恢复；
- 显式 `Recover()` 后从最近一次完整提交状态继续，且每个周期号至多注入一次，
  恢复后重跑同一周期号不会再次注入；
- 该手段仅面向本地演练：默认关闭，关闭时对正常运行的语义、确定性与并发安全零影响。

## 热重载原子性

`Reload(新源码, 新配置)` 在扫描周期边界整体替换程序：

- 新程序先在临时对象上完成全部启动前校验、保持布局构建与保持文件兼容性判断；
- 任一环节失败：返回 `Applied=false` 与原因（`ValidationRejected` / `RetainIncompatible`），
  **旧程序、旧输出、旧状态原样继续**，不存在新旧指令混执行；
- 全部通过后持锁整体切换 `Program/DataTable/Config/RetainStore`，并立刻整包同步一次新输出映像，
  切换瞬间外部不会看到混合输出。

由于扫描与重载共享同一把锁，二者并发调用只会被串行化（`-race` 下有对应用例）。
