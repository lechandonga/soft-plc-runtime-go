# 掉电保持规则

## 哪些数据可保持

在配置文件 `retain` 数组中按地址名称显式声明：

- 允许：`M` 区位与字（如 `M0.0`、`MW2`）、`Q` 区位与字、计数器当前值（`Cn`，保存 CV；Q 按恢复后的 PV 重新判定）。
- 不允许：输入区 `I`、定时器（时间随扫描推进，保持无确定语义）、立即数。
- 保持项必须在程序中被引用；重复或重叠、悬空引用一律拒绝启动。

## 兼容判定（宁可拒绝，不能错位）

保持文件头部同时记录两个指纹：

- **程序指纹**：源程序文本的 SHA-256。程序任何改动（版本/结构变化）都改变它，
  恢复时不一致返回 `ProgramChanged`，拒绝启动/热重载。
- **保持布局指纹**：保持项名称、区域、偏移、宽度与排序的 SHA-256。
  保持项增删改、地址偏移变化都改变它，不一致返回 `LayoutChanged`。

只有两个指纹都一致才恢复；热重载遇到已有保持文件不兼容时整体拒绝并继续运行旧程序。
如需在程序升级后冷启动，显式删除/更换保持文件路径即可（这是一个有意的人工动作，系统不擅自丢弃数据）。

## 文件格式与原子提交

文件：`magic "SPLCRET1" | programHash(32) | layoutHash(32) | sequence(8) | 位项表 | 字项表 | 整包SHA256(32)`

- 写入流程：写 `xxx.tmp` 临时文件 → `Sync()` → `rename()` 原子改名 → 目录 fsync。
  写到一半时崩溃只会留下不完整的临时文件，正式文件永远是**最近一次完整提交**。
- 读取流程：检查魔数与长度 → 校验整包 SHA-256 → 逐项解码并核对结构长度。
  截断、撕裂、篡改、尾部多余字节都判为 `Corrupt`，拒绝启动。
- `sequence` 是提交时的扫描计数，可用于人工判断文件新旧。

提交时机：每个扫描周期“输入采样 → 执行 → 输出提交”全部成功后才写保持文件；
保持写入失败时该周期进入 `RetainFault`（过程状态不回滚外部已提交输出，但输出落安全值并锁存），
从而不会出现“输出已变、保持丢失”且无人知晓的静默分歧。

## 重启恢复语义

- 有保持文件且双指纹一致：仅把声明的保持项写回冷态数据表，其余（定时器、边沿历史、非保持 M/Q）冷启动。
- 无保持文件：合法冷启动，全部数据为 0。
- 文件损坏/版本不符/布局不符：返回明确错误，`NewRuntime` 拒绝启动。

端到端验证见 `TestE2EBinaryRetainAcrossProcesses`：两个独立 CLI 进程通过同一个保持文件接力计数，
第二个进程从第一个进程最后一次完整提交的 CV 继续。
